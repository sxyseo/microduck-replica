# 称重与标定模板 — HD-1910 版

> 目的：在训练之前，把"我们的机器人模型是否真实"这件事用实测数据锚定。
> 三层区分（本文件只服务第一层；BAM 标定与 XL330 对齐是另外两层，见 §F）：
>
> 1. **模型保真** —— 重量、重心、惯量、几何 ← 本模板
> 2. **BAM 标定** —— HD-1910 是否像真实 HD-1910
> 3. **XL330 对齐** —— HD-1910 能否复现官方策略的动作效果（部署端旋钮，不改 BAM）
>
> 红线：**不能为了"像 XL330"而修改实测 BAM / 真实质量 / 真实质心。**

## 0.6 kissqy 参照的使用边界（2026-10-07 核验）

`kissqy/Microduck-kissqy` 是目前最接近本机的参考工程（同官方骨架 + 同 15 颗 HD-1910 + 同 Zero 3W），
定位是 **HD1910 基线和代码移植来源**，不是本机的最终标定，**不建议整包安装到 Zero 3W**：

1. **BAM 身份**：`hd1910_m6.json` 与 XGODUCK 的 `1910_m6.json` 字节级相同（`ef2d51ad…`）——
   它是陆吾/XGODUCK 的参考参数，既不是 kissqy 对其 15 颗舵机的重新实测，更不是我们的实测。
2. **820g 模型**：可当第一版仿真基线（`hd1910_kissqy_reference_m6`）；质心沿用官方、惯量按
   质量比缩放，仓库自己承认是近似。最终必须换成我们的实测分区（§B）。
3. **Console ZIP 已损坏**：`release-assets/Microduck-Console-R17-v1.0.146-Public.zip` 实际
   `1749bc2c…`（17,897,782 B，git blob 本身截断）vs 声明 `cd1503a4…`（24,435,137 B）——
   **勿使用**；固件 ZIP 与 Training ZIP 完好。本地已启动的中控跑的是 `firmware/console/` 源码，不受影响。
4. **不整包安装 R17**：它钉在官方 daemon 0.15.1 旧基线（API40），整包安装 = 把设备降到旧版大分叉。
   正确路径：**把 HD1910 总线后端（feetech.rs）、临时 P/D 写入+读回+卸力恢复（hd1910.rs）、
   标定门控（hd1910-calibration.template.toml）、FT6 HAT/IMU 支持**移植进当前 microduck 代码。
5. **样机零位绝不复制**：作者自己的 head_roll 曾从 568 改到 1599（差 1031 计数 ≈ 90.6°）——
   同 CAD、同 ID、同舵机也不能共用 zero_raw。安全模板默认 `motion_enabled=false`、
   `imu_mount_verified=false`、15 关节全部确认后才允许运动。
6. **模型验收状态**：联合 Walk（VelStand-Rough-Backlash，2560 env × 9600 轮，model_9599）
   `deployment_verified=false`——未完成真实 Zero 闭环步态/背部起身验收；走路/保持/倒地全部
   用 0.9/0.5/0.7（只有独立 LB 起身老师 1/1/1）；2560×9600 与 4096×6000 样本数相同但
   优化更新次数不同，不等价。
7. **sim-to-real 缺口**：训练侧 STS3215/BAM 控制结构未完整模拟真机 D=20——P 相同 ≠ 响应对齐。

## A. 整机总重（三次重复称量，当前阶段唯一要做的事）

**规程**：
1. 秤空载归零；记录电子秤型号与分度值；
2. 每种状态**连续称 3 次**（不挪动重新放置不算复测）；
3. 机器每次放置方向相同；线材不得搭在桌面/秤上；
4. 拍照留档：秤显示 × 每次读数、含/不含电池两种状态。

```text
电子秤：
分度值：

不含电池：
第1次：        第2次：        第3次：        平均：

含电池（最终 NP-F550）：
第1次：        第2次：        第3次：        平均：

电池单独：
第1次：        第2次：        第3次：        平均：
```

**误差标准**：最终误差由秤分度值与三次重复的离散度决定；模板里任何百分比只作初筛。

## F. 后两层与训练路线（备忘）

- **BAM 标定（第二层）**：输入=目标位置/P/电压/已知负载/实测位置·速度·电流·温度；输出=电机常数与电阻、
  摩擦(Stribeck)/黏性/负载相关、转子惯量、命令延迟、速度饱和。
- **XL330 对齐（第三层）**：同轨迹台架对比（±5/10/20° 阶跃、0.2–2Hz 正弦、三角波、快速反转、
  多负载多电压），出响应差异表 → 决定 P、action scale、头腿低通、按技能关滤波、每关节缩放。
  没有 XL330 实机时，用官方 XL330 BAM 做"**仿真对齐**"，不得称"实机对齐"。
  部署端现状：`robotd` 把头/腿低通应用到**所有**策略（`robotd/src/control.rs`、`deploy/robotd.toml`），
  动态技能（起身/翻滚/捡球）可能被滤波拖垮——按策略在 manifest 区分是后续代码改动，先不动。

**训练路线（官方 develop 现状）**：

```bash
# 快速基线/冒烟（Flat 仍在官方仓库里，用于排错与基线——"Flat 已弃用"的说法不准确）
uv run train Mjlab-Velocity-Flat-XgoDuck ...

# 最终生产（Rough；若注册了 Backlash 版本才进一步用 Rough-Backlash）
uv run train Mjlab-Velocity-Rough-XgoDuck ...
```

官方生产流程（`docs/velstand_policy.md`，上游 develop）：walk teacher + stand/get-up teacher
→ VelStand student → PPO + fallen 状态起身教师 BC + upright 状态走路教师锚定 → **Rough+Backlash 联合策略**。
⚠️ 本地克隆 `29e887e` 尚无 `distill.py`（有 velstand env cfg）——需要单独更新克隆获取联合训练管线，
**不得在钉死的基线克隆上直接 pull**。

**并行数换算**：官方 4096 env × 24 步 = 98,304 transitions/迭代；换环境数时课程迭代数按
`官方迭代 × 4096 / 新env数` 换算——**但源码里部分 curriculum 计数单位是 `iteration × 24`（不乘 env 数）**，
正式训练前必须逐个列出每个 curriculum 的计数单位（optimizer iteration / common_step_counter /
单环境步数 / 总 transitions），否则课程错位、惩罚时机错误。
