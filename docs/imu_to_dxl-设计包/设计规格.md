## 一、这块板是干什么的（一句话）

**让 IMU 伪装成一个 Dynamixel 舵机**，和 15 个真舵机在同一次 `sync_read` 里被读回——主机不跑姿态融合（LSM6DSV16X 片上 SFLP 直接出四元数），不占第二条总线。

## 三、系统框图【设计】

```
 总线 V+ (7.4V 2S, 6.6–8.4V)
   │
   ├─ HT7333 LDO → 3.3V ──────────────┐
   │                                  │
JST-EH-3P ○── DATA ──┬─ RX 直连 ──────┤
(入)                 │ (100Ω 串阻)    │
                     └─ [SN74LVC1G126 缓冲] ○── MCU USART1_TX (PA9)
                          OE ← PA8，10k 下拉（默认断开，防上电抢线）
                                                      │
                                              STM32G031F8P6
                                                      │ I2C1 400kHz (PB6/PB7)
                                              LSM6DSV16X (0x6A)
                                                ├ INT1 → PA0 (EXTI，可选)
                                                └ SA0 → GND
JST-EH-3P ○── 同一 DATA/GND/V+ 总线（出，菊花链）
(出)
SWD 4P 排针（PA13/PA14 + 3V3 + GND）
```

### 关键设计决策

1. **半双工方案：缓冲器优于原生单线**【设计】。
   STM32 原生 HDSEL 模式也能单线收发（少一颗料），但上电瞬间引脚是浮动态，可能与总线冲突；
   `SN74LVC1G126` 的 OE 挂 10k 下拉 = **上电默认断开**，固件初始化完成才接通。15 个舵机的总线，安全第一。
2. **不设计电池电压测量**【已验证】：主机直接读舵机自报电压（`bus.rs` L339–355，寄存器 144–146），本板不需要任何 ADC/分压。
3. **量程锁定 ±500 dps**【已验证】：主机按 17.5 mdps/LSB 换算，固件若配别的量程，主机读到的角速度整体错倍数。
4. **连接器 JST EH 2.5mm 3P**【已验证·勘误过】：与官方 HAT 及飞特 5264 线材同间距；上一版设计里的 PH 2.0 要改。

## 四、引脚分配（STM32G031F8P6, TSSOP20）【设计】

| 引脚 | 信号 | 说明 |
|---|---|---|
| PA9 | USART1_TX → 缓冲器 IN | 1 Mbps，AF 复用【AF 编号以数据手册核对】 |
| PA10 | USART1_RX ← 总线 | 与 TX 同一 DATA 线 |
| PA8 | GPIO 输出 → 缓冲器 OE | 发送前置 1，发完回 0 |
| PB6 / PB7 | I2C1_SCL/SDA | 400 kHz，外接 4.7k 上拉 |
| PA0 | LSM INT1（EXTI） | 可选：数据就绪中断采样，骨架先用轮询 |
| PA13/PA14 | SWDIO/SWCLK | 调试排针 |
| — | LED（PB 口任一） | 异常/心跳指示 |

## 五、寄存器块（本板在总线上的全部真相）【设计】

```
地址 124 起，20 字节（主机 sync_read 只取前 12）：
 124+0   i16 LE ×3   陀螺原始计数（±500 dps 满量程）
 124+6   fp16 LE ×3   SFLP game rotation x/y/z
 124+12  i16 LE ×3    原始加计（自定诊断）
 124+18  u8           采样计数器（查跳帧）
 124+19  u8           状态标志（bit0 = 最近一次 I2C 读失败）
```
标准控制表（0=型号 200、6=固件版本、7=ID、8=波特索引 3 只读、9=应答延迟）已在固件协议层实现。

## 六、时序预算【已验证·计算】

应答状态包 = 4 头 + 1 ID + 2 LEN + 1 INST + 1 ERR + 12 数据 + 2 CRC = **23 字节 ≈ 230 µs @1Mbps**。
16 台设备 × ~250µs + 间隔 ≈ **4–5 ms**，只占 20ms tick 的 1/4，距 30ms 主机超时余量充足。

## 七、验收清单（打样回来照此走）

1. **单板裸测**：USB-TTL（1Mbps）发 PING(200) → 收 11 字节状态包（协议层测试已验证包格式）
2. **READ 124/12**：晃动板子，陀螺 3 个 i16 变化；静置，四元数趋近 (0,0,0)+w=1（fp16 的 xyz≈0）
3. **联机冒烟**：接到 Radxa `/dev/ttyS2`，跑 `duck-control` 的总线自检，确认 16 台设备一次 sync_read 全回
4. **50Hz 连续运行**：`robotd` 控制环跑 10 分钟无 bus 错误日志
