# Microduck RL 复刻 · 30 天计划（公众号系列配套）

> **系列定位**：源码拆解 + 可复现实验 + 复刻过程。不是代码翻译。
> **每篇文章的骨架**：我改了什么 → 为什么改 → 怎么运行 → 指标如何变化 → 结论和失败原因。
> **诚实性标签**（每篇文章必须用）：`【已验证】`我实际运行过 / `【推测】`根据代码推断 / `【未完成】`还没有验证。
> **开始日期**：2026-09-05　**结束**：2026-10-04
> **本机条件**：Mac mini（Apple Silicon，无 CUDA）→ 小实验本机 CPU 可跑；正式训练走 GPU 机器或 HuggingFace Jobs（`--hf-jobs`，官方内置支持）。

---

## 主链路（整个系列就是把它拆开讲完）

```
任务注册 → 环境配置 → observation/action → MuJoCo 仿真 → reward
        → PPO 更新 → checkpoint → ONNX → 机器人运行时(Rust)
```

对应代码（均已核实存在，行号以当前上游 commit `29e887e` 为准）：

| 环节 | 文件 |
|---|---|
| 任务注册 | `microduck_rl/src/mjlab_microduck/tasks/__init__.py`（L81 起 `register_mjlab_task`） |
| 环境配置 | `tasks/microduck_velocity_env_cfg.py`（949 行） |
| MDP 真实现 | `tasks/mdp.py`（7188 行：reward/obs/reset/DR/curriculum 的数学） |
| 常量/HOME 姿态 | `robot/microduck_constants.py`（275 行） |
| 训练/回放 | `uv run train` / `uv run play` / `uv run list-envs` |
| 导出推理 | `scripts/infer_policy.py`（1524 行）、`export.py` |
| 机器人运行时 | `duck-control/src/obs.rs`（OBS_LEN=61）、`duck-control/src/policy.rs`（ONNX 加载） |

### D10 · exp001 正式执行（A 组）
- A 组 = 默认配置（`ENABLE_IMU_ORIENTATION_RANDOMIZATION = True`，L40，角度 6°，L84）。
- 命令：`bash experiments/exp001-imu-randomization/run_a.sh`（本机过夜，或 `--hf-jobs`）。

### D11 · exp001 B 组
- B 组 = 应用 `exp001.patch`（把开关改 `False`），命令 `run_b.sh`。其余参数一律不动。

### D12 · 对比与结论
- `python scripts/plot_ab_compare.py --a <A> --b <B> --tags ... --out 对比.png`
- 判定标准（写进 README）：两者 `mean_reward` 差异是否显著、`fell_over` 收敛差异。
- 产出：exp001 记录 A/B 填完 → 文章 08 素材。

### D13 · L532–638：61 维 / 76 维怎么来的
- **硬证据已拿到**：训练产物 ONNX 输入 `obs[1,61]`、输出 `actions[1,14]`；Rust 侧布局 `3+3+14+14+14+13=61`。
- critic 76 = actor 61 + 特权信息（base_lin_vel 等），env.yaml 里逐项数。
- 产出：文章 06 完稿（配图已生成：`assets/obs-61维布局.png`）。

### D14 · L639–748 指令系统 + 周复盘
- twist(3) / head_pose(4) / body_pose(6) = 13 维指令块；`TURN_IN_PLACE_FRACTION=0.15` 的动机（文件头注释写了：独立均匀采样会让原地转只占 2% 数据）。
- 发布：文章 04、05。

**W2 退出标准**：exp001 有 A/B 完整记录和一张对比图；能不看书写出 61 维的构成。

## 第 3 周：reward / DR / sim2real + 真正的训练（文章 08–10）

### D15 · 配置 vs 数学分家
- 关键认知：`cfg.rewards["track_linear_velocity"].weight = 2.0`（L342）只是权重，公式在 `mdp.py`。
- 读 `mdp.py` 里 `feet_air_time_upright`、`fallen_state_penalty`、`com_upward_velocity` 等函数。

### D16 · L749–917 curriculum
- 实例：`action_rate_weight` 从 -0.1 分五档 ramp 到 -1.0（iter 1500 收紧）——代码真实存在，摘录进文章。

### D17 · L928–950 PPO 参数
- MLP 512-256-128 + elu、lr=1e-3 adaptive（desired_kl=0.01）、γ=0.99、λ=0.95、mini-batch 4。

### D18–19 · 发起正式 GPU 训练（200 迭代起）
- 路径二选一：本地/借用的 GPU 机器（2080/3080/4090 记录 `nvidia-smi` 与迭代耗时）或 `uv run train ... --hf-jobs`。
- 期间写：文章 07《reward 函数到底在奖励什么》完稿。

### D20 · GPU 对比数据（文章 09）
- 同一任务、同迭代数，在 2080/3080/4090（或 HF Jobs 的 GPU 型号）各记：it/s、显存、单迭代耗时。**没有 GPU 就诚实测一次 + 引用官方 num_envs=4096 的规模感**。

### D21 · checkpoint → ONNX
- 训练目录自带 `.onnx`；用 `scripts/inspect_onnx.py` 验证形状（61/14）。
- 对比新旧产物：`logs/.../2026-09-05_00-23-33_lesson-01.onnx`。
- 发布：文章 06、07。

**W3 退出标准**：一次 ≥200 迭代的 GPU 训练完成；ONNX 形状验证通过；exp001 结论成文（文章 08）。
