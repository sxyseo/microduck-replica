# 02 · OpenMicroDuck、microduck-replica、microduck_rl 到底什么关系？

> 状态：**可发布**（关系图可再配一张手绘图）
> 事实状态：全部 `【已验证】`（逐个仓库读过）

研究 MicroDuck 的第一道坎是分清楚 GitHub 上那一堆「鸭」。我一开始也混过：以为所有资料都在一个主仓库里，结果漏掉了整个硬件开源仓库（这个教训我在 microduck-replica 里公开勘误过）。这篇把三个最容易混淆的项目一次说清。

## 三者关系

```
Pollen Robotics（官方）
├── microduck        —— 机器人「身体」上的软件：Rust 写的控制系统、更新器、蓝牙、
│                       摄像头串流……（Apache-2.0，完整开源）
└── microduck_rl     —— 机器人「大脑」的训练场：MuJoCo + PPO 强化学习，
                        训练出 ONNX 策略文件喂给上面的运行时（本系列主角）

我 / 社区
├── microduck-replica —— 我对机械与电控的第三方复刻研究：从公开 MJCF 反推
│                        装配图、紧固件、电控方案（纸上分析 + 构建日志）
└── OpenMicroDuck     —— 社区的完全开源复刻计划：国产供应链平替
                         （Feetech 舵机、RK3566 板、18650 电池），路线图 M1–M5
```

## 一个关键区别：身体开源，大脑也开源，但「说明书」不全

- **`microduck`（身体软件）**：Apache-2.0，毫无保留。它甚至把设计决策写在 `docs/design/` 里——为什么更新器要健康门控、为什么重启顺序不能错。这是我见过注释文化最好的机器人仓库之一。
- **`microduck_rl`（大脑训练）**：同样开源，而且**训练产物也公开**（9 个 ONNX 策略）。只要你硬件照抄官方，这些大脑直接能用。
- **硬件**：部分开源。RPI Robot HAT 板有完整 KiCad 工程；但 `imu_to_dxl` 板、可编辑机械 CAD、装配文档没有公开——这正是 microduck-replica 在补的窟窿。

## 为什么本系列只盯着 microduck_rl

因为我的复刻路径是「机械照抄 + 电控自建」。机械照抄的终点是**装出一只能站着的鸭子**；要它能**走起来**，要么用官方 ONNX（前提是硬件完全同款），要么自己重训。而只要我动了硬件——比如换掉那块不开源的 IMU 板——官方策略就全部失效，必须用 `microduck_rl` 重训。

所以读懂这个仓库，不是兴趣，是我的复刻路线图上绕不开的一站。

## 给同样想入场的人

- 只想养一只鸭子 → 等官方发售（$399）。
- 想复刻硬件 → microduck-replica + OpenMicroDuck 都可以看，后者配套更全。
- 想学机器人强化学习 → 直接读 `microduck_rl`，跟着本系列做实验。
