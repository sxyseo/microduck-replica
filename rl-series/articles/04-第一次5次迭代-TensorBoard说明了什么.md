# 04 · 第一次只训 5 个迭代，TensorBoard 告诉了我什么

> 状态：**可发布**
> 事实状态：本文指标全部 `【已验证】`——从 `logs/rsl_rl/velocity/` 下真实事件文件提取，非手抄截图

> 骨架：我改了什么（什么都不改，只跑通）→ 为什么 → 怎么运行 → 指标如何变化 → 结论

## 我改了什么

**什么都没改。** 第一个实验的目的不是让鸭子学会走路，而是验证整条链路：

```
train 命令 → MuJoCo 仿真 → PPO 更新 → checkpoint(model_N.pt) → TensorBoard → ONNX 导出
```

这叫冒烟测试，官方 AGENTS.md 也这么要求：任何正式训练前，先跑一个 5 迭代的小的。

## 怎么运行的

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck \
    --env.scene.num-envs 64 \
    --agent.max_iterations 5
uv run tensorboard --logdir logs/rsl_rl
```

跑完 `logs/rsl_rl/velocity/<时间戳>_lesson-01/` 目录下应该有：`model_0.pt` 到 `model_4.pt`（5 个 checkpoint）、一个同名的 `.onnx`（自动导出）、`params/`（env.yaml + agent.yaml 参数快照）、`git/`（代码 diff 快照）。**训练目录自带完整案发现场**——这个习惯值得所有实验型项目学习。

## 指标如何变化（真实数据）

我写了脚本直接解析事件文件（`rl-series/scripts/extract_tb_metrics.py`），以下是 `lesson-01` 那次运行的原值：

| iteration | Train/mean_reward | fell_over | error_vel_xy | error_vel_yaw | Policy/mean_std |
|---|---|---|---|---|---|
| 0 | — | 0.000 | 0.000 | 0.000 | 1.000 |
| 1 | **-0.061** | 1.375 | 0.024 | 0.137 | 1.000 |
| 2 | 0.007 | 1.000 | 0.032 | 0.135 | 1.000 |
| 3 | 0.090 | 1.000 | 0.035 | 0.153 | 0.999 |
| 4 | **0.095** | 1.000 | 0.028 | 0.172 | 0.999 |

（图为 `assets/lesson01-首次5次迭代真实曲线.png`）

## 逐条解读

1. **mean_reward 从 -0.061 爬到 0.095**：曲线在涨，说明 reward 信号、梯度、PPO 更新都活了。但绝对值小得可怜——这只是「学习机器在转」，不是「学会走路」。
2. **fell_over 稳定在 1.0**：每个 episode 平均摔倒一次。鸭子站起来→走两步→摔。5 个迭代（8 环境也才几百秒的仿真经验）当然学不会，这条曲线要跌下去才算入门。
3. **error_vel_yaw 反而从 0.137 涨到 0.172**：最有意思的一条。转向误差在变大——可能因为策略开始乱动（探索），而 reward 里转向跟踪的权重（`track_angular_velocity.weight = 2.0`）还不够压制其他项。**【推测】**这是正常的早期震荡，如果 500 迭代后还涨就是 reward 设计问题，到时候再回头改。
4. **Policy/mean_std 卡在 0.999**：这个值是策略的探索噪声幅度。它几乎不动，说明策略还在「什么都试试」的阶段。学会走路的过程，应该看到它缓慢下降（策略越来越确定）。

## 结论与下一步

> 【已验证】5 次迭代成功验证了训练、TensorBoard、checkpoint 和 ONNX 导出链路，但鸭子还没有学会稳定走路——每集都摔。
> 【未完成】要看到真实的「学习曲线」，需要 50–200+ 迭代量级的正式训练，那是 exp001（A/B 对比实验）和第 3 周 GPU 长跑的事。

失败不需要难过：这一轮最大的产出不是一只会走的鸭子，而是**一套可信的基线**。下一篇文章开始，我们改第一个变量。
